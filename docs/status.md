- **Built so far:** the repo root (npm workspaces, shared TypeScript settings, `.env.example`) and four parts. The API in `services/api` checks who is calling and which company they belong to, and has three addresses: `/v1/health`, `/v1/me`, which answers with the signed-in user's company and role, and `/v1/demo-work`: `POST` starts a demo run (it saves a row in `work_runs`, then queues a work item, and answers at once) and `GET` lists the company's last ten runs. It reaches Supabase with the secret key, gives every log line a request ID, answers errors in one clean shape and allows the web app's address through CORS. It also holds the script behind `npm run company:create` and `npm run company:add-user`. Core in `packages/core` holds the winston logger, the settings loader, the database connection, the repository for `work_runs` and the work queue (BullMQ on Redis, one queue named `demo`), and is read as TypeScript source in development. The worker in `services/worker` keeps running: it listens to the queue, runs each demo work item, keeps the run's row in Postgres in step (waiting, running, done or failed), tries a failed item again up to three times, and finishes the running item before it stops. It also holds two development scripts, `npm run mailbox:connect` and `npm run mailbox:check`. The web app in `apps/web` (Next.js 16) has sign-in and sign-out and a shell around every signed-in page: a top bar with the product's name, a menu of two items (Home, Jobs), the company name, the user's email and a "Sign out" button. Its pages are a sign-in page at `/signin`, a home page at `/` with a "Jobs" section and a temporary "Queue demo" section with five buttons (run now, run in 20 seconds, fail once, always fail, slow) and a list of the last runs read from Postgres, and a placeholder page at `/jobs`. The shell asks `/v1/me` once and shares the answer with every page through a React context (`useMe()`). The look is set: light mode only, the navy, cream, purple and light navy of the NexRhino colour guide written once in `globals.css`, navy buttons from one shared constant, and the Geist font. The session is kept in the browser's local storage by the Supabase library, a browser-side guard sends a visitor with no session to the sign-in page, and every screen calls the API through the helper `apiFetch`, which attaches the token itself. The web app has ESLint with the Next.js rules. How it all works is in `docs/developer-guide.md`, and the table map is in `docs/table-map.md`.
