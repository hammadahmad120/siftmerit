- **Built so far:** the repo root (npm workspaces, shared TypeScript settings, `.env.example`) and four parts. The API in `services/api` checks who is calling and which company they belong to, and has two addresses: `/v1/health` and `/v1/me`, which answers with the signed-in user's company and role. It reaches Supabase with the secret key, gives every log line a request ID, answers errors in one clean shape and allows the web app's address through CORS. It also holds the script behind `npm run company:create` and `npm run company:add-user`. Core in `packages/core` holds the winston logger and the settings loader, and is read as TypeScript source in development. The worker in `services/worker` logs one start line and finishes; it has no queue yet. It also holds two development scripts, `npm run mailbox:connect` and `npm run mailbox:check`. The web app in `apps/web` (Next.js 16) has sign-in and sign-out and a shell around every signed-in page: a top bar with the product's name, a menu of two items (Home, Jobs), the company name, the user's email and a "Sign out" button. Its pages are a sign-in page at `/signin`, a home page at `/` with a "Jobs" section, and a placeholder page at `/jobs`. The shell asks `/v1/me` once and shares the answer with every page through a React context (`useMe()`). The look is set: light mode only, the navy, cream, purple and light navy of the NexRhino colour guide written once in `globals.css`, navy buttons from one shared constant, and the Geist font. The session is kept in the browser's local storage by the Supabase library, a browser-side guard sends a visitor with no session to the sign-in page, and every screen calls the API through the helper `apiFetch`, which attaches the token itself. The web app has ESLint with the Next.js rules. How it all works is in `docs/developer-guide.md`, and the table map is in `docs/table-map.md`.
